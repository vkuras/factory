## G1 – The designed match rule contradicts the requirements
- Status: Open
- Design: docs/architecture/002-find-a-task.md, "Decisions" and "Interfaces" ("The match is a prefix match on the title, compared case-sensitively", `title.startsWith(q)`)
- Requirement: R4, S5.2, S5.3 (and, downstream, S5.1, S5.4, S5.5, S6.2, which all depend on what a search actually matches)
- Problem: The design specifies a case-sensitive prefix match (`title.startsWith(q)`). The requirements ask for the opposite, twice over: R4 says "A search matches when the typed text occurs anywhere in the task's title, comparing without regard to upper and lower case", and gives the worked example "milk" matching "Buy Milk", "Order milk crate" and "MILK" — none of which start with "milk". S5.2 and S5.3 test exactly this: case-insensitivity and mid-string matches. The appendix trace backs it with the stakeholder's own words: "I type milk and I want to see everything with milk in it" (L2), "I never know how somebody wrote it down" (L3), "Exact letters, just anywhere in the text" (L4). No ADR documents a deviation — ADR-0003 only decides *where* the filter runs (the list endpoint vs. a separate endpoint), never the match rule. As written, the design's own worked interface would fail S5.2 and S5.3 of the requirements it exists to satisfy.
- Blocks: S5.1, S5.2, S5.3, S5.4, S5.5, R4, S6.2 (the combination of "open only" with a search term). S6.1 and S6.3 don't depend on the match rule and are built in this round.
- Suggestion: Implement `matchesQuery()` as the requirements state it — `title.toLowerCase().includes(q.toLowerCase())` — an anywhere, case-insensitive substring match. At the stated scale (500 in-memory titles, QE5) this is still sub-millisecond: a `toLowerCase()` + `includes()` over a few hundred short strings costs microseconds, so QE5's p95-under-500ms budget is not at risk. Recommend updating the design's Decisions/Interfaces sections to this rule; if there's a reason to keep a prefix match despite the requirements, that needs a requirements change instead, not a silent design choice.
