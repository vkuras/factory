Das Design für 002 liegt in `docs/architecture/002-shopping-list.md` (dazu ADRs 0005–0008 und ein aktualisiertes `overview.md`). Die Einkaufsliste wird als neues `shopping`-Modul im bestehenden Ktor/Postgres-Backend gebaut. Live-Updates laufen über SSE, offline wird über einen IndexedDB-Snapshot mit Outbox abgehakt, und ein Revisionscheck sorgt dafür, dass beim Mergen keine Mengen verloren gehen. Bereiche kommen aus Haushaltskorrekturen und einem Wörterbuch, alles andere landet in „Sonstiges“. Im Laden erreicht man den Pi über Tailscale.
Konflikt: Firebase wird nicht verwendet, weil die Daten laut 001 komplett auf dem Pi laufen müssen. Der Change Request dazu liegt in `docs/requirements/.change-requests/002-shopping-list.md`.
